## 三、手動中斷的處理語意

9f44bb9-1 原 todo 修法寫「加 `if: always()`」。**字面 `always()` 的 GitHub 語意是連手動取消（cancelled）都會執行**——被取消的 Python 進程可能死在 `save_state()`/`write_coupons_js()` 中途，留下截斷的半成品檔案；always 的 commit step 會把這種檔案推上 main（scan_state.json 損壞＝次日整條鏈崩）。正確條件是 `if: !cancelled()`：

| 情境 | `if: always()`（todo 原修法） | `if: !cancelled()`（本分析修正） |
|---|---|---|
| 熔斷（exit 3）／步驟失敗 | commit 已寫檔的完整結果 ✓（修復目標） | 同左 ✓ |
| **手動取消 run** | **commit 半成品——有截斷檔上 main 的風險 ✗** | **不 commit：半成品留在 runner 銷毀，main 不動，下次重跑自乾櫃狀態開始 ✓** |
| 停用 workflow／cron 暫停（現況） | 無 run，無行為 | 同左 |

告警對稱性：alert job 的 `if: failure()` 在 cancelled 時不成立——手動取消不會誤開紅 issue ✓。取消落在 push 循環中段：push 是原子的，main 只會收到完整 commit ✓。

語意總結：**失敗要撿（熔斷日資料保全）、取消不撿（半成品丟棄）**。
