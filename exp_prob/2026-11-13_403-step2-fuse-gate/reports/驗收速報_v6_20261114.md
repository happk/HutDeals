
## 隱含假設：⑥a′ 的 `is None` 依賴「parse 鏈不會產生 `[]`」

### 問題

v6 的 ⑥a′ 條件是 `if r.get("items") is None and rec["code"] not in ITEMS_NONE_WHITELIST`。
白名單三碼的實際值：

| 碼 | `items` | `is None` | 白名單條目作用 |
|---|---|---|---|
| 93015 | `[]` | **False** | **no-op（不會被抓，白名單無意義）** |
| 15596 | `None` | True | 有效 |
| 16348 | `None` | True | 有效 |

**93015 的白名單條目實際上是無效的**——因為 `[] is None` 是 `False`，它本來就不會被 ⑥a′ 抓。

### 這無害，但暴露了一個未明寫的假設

我驗證了 `flatten_items` 的結尾：

```python
if not items:
    return None
return items
```

**空結構回 `None`，不回 `[]`。** 所以：

- 垃圾頁路徑：`parse_menu_html` → `flatten_items` → `None` → `fetch_and_parse` → `step2_of` → `items=None` ✅ ⑥a′ 抓得到
- `[]` 的來源：只可能是 `daily.py:209` 的 `rec.get("items") or []`（比對用，不寫回）
  或 `scan_probe/scan_run` 的 `r["items"] or []`（手動工具）
- 93015 的 `[]` 是歷史遺留（`source=None`、`lastSeen=2026-09-04`，非現行管線寫入）

### 為什麼要寫進未解事項

若未來官網改版讓 `flatten_items` 回 `[]` 而非 `None`，⑥a′ 的 `is None` 會**靜默失效**——
垃圾頁被當成正常券放行，而且不會有任何告警。

**建議**：在未解事項加一條——

> ⑥a′ 的判定依賴「`flatten_items` 空結構回 `None` 而非 `[]`」。
> 若 `parse_orderflow.flatten_items` 的契約改變（回 `[]`），⑥a′ 會靜默失效。
> Phase 8 觀察時應留意是否有 `items=[]` 的新記錄出現。

另一個選項是把判定改成 `if not r.get("items")`（同時抓 `None` 與 `[]`），
但這樣 93015 會被誤抓——所以必須保留白名單，且白名單的三碼都必須列（現在的三碼是對的）。
**兩個方案都可行，v6 選 `is None` 是更保守的選擇**（不誤傷 93015），代價是要靠文檔記錄這個假設。
