## 操作中留意的事

- **mock 層級＝證偽力**（三規則對應三次教訓）：cmd 層 mock `daily.fetch_and_parse`、不 mock `step2_of`；③a 測試在 orderflow 層；⑥a 閘門測試 mock 只放下游回傳值。
- **兩個既有守門員**：`test_step2_visibility::test_exception_recorded`（③b）與 `test_fetch_retry` URLError 案例——綠燈且語意不變才算過。
- **enrich 與 daily 四處形狀差異是刻意的**（daily 非熔斷直拋／enrich 非關鍵字照舊 SKIP）——不要為一致而改語意。
- **⑥a′ 是關鍵新增**：假成功到不了 cmd 層——若 cmd 層還需要收窄歸零邏輯，代表 ⑥a′ 沒放對位置，回查。
- **⑦b 的字串清單**：explore/sample 必須先建 `[r["code"] for r in ...]`——`fresh`/`hits` 是 rec dict，直接傳會 KeyError（probe 實證）；「**邊界宣告不修的檔案仍會被核心改動炸掉**」（seg_gap）與「**補法本身要驗**」（enumerate/KeyError）是第五輪的兩個新教訓。
- **白名單是回滾槓桿＋需監控**：正常日 exit 3 且 log 顯示「疑似垃圾頁」→ 確認後加白名單；**最長連續非白名單區段 <3 時 ⑥b 失效（今日 306/312/4，最短段餘裕 1）——Phase 8 觀察**。
- **煙霧零污染＋計時**；main 前進先 rebase；反向測試「該擋的時候真的擋」才算證明。
- 任一層漏改都會被對應案例抓出（3.5 五案例／4.5 四案例／1.4 pacing 單元）。

## 失敗／回滾判準

- 任一落點驗證失敗 → 只回滾該落點；①/②③/④⑤⑧/⑥/⑦ 六組互不依賴，可各自單獨回滾。
- 修改① 誤傷 500/超時重配 → 立即回滾重檢。
- ③a 誤傷非關鍵字重試 → 守門員與案例三抓出 → 回滾收緊。
- ⑦ 若煙霧/CI 顯示間隔異常或官網反應變化 → `DEFAULT_SLEEP` 調回 2.0（一行）；若工具受影響 → `DEFAULT_SEG_GAP` 調回 15.0（一行）——⑦ 的回滾成本最低。
- ⑥a 門檻誤傷正常頁（全碼解析失敗＋exit 3）→ 單獨 revert ⑥a。
- ⑥a′/⑥b 誤熔斷（無選項券相鄰）→ 白名單加入該碼；持續誤熔斷 → revert ⑥b 或放寬 N。
- ⑤ gh 服務端故障誤擋一日 → 可接受，不回滾。
- 上線後正常日 exit 3 → 立即 revert＋重查關鍵字與門檻。
