## 操作中留意的事

- **mock 層級＝證偽力**：cmd 層測試 mock `daily.fetch_and_parse`、不 mock `step2_of`；③a 測試必須在 orderflow 層；
  ⑥a 閘門測試 mock 只放 `parse_menu_html` 回傳值——三條規則對應三次教訓（v2 假陽性、第三輪阻斷二、第三輪機制描述錯誤）。
- **兩個既有守門員**：`test_step2_visibility::test_exception_recorded`（③b）與 `test_fetch_retry` URLError 案例——綠燈且語意不變才算過。
- **enrich 與 daily 四處形狀差異是刻意的**（daily 非熔斷直拋／enrich 非關鍵字照舊 SKIP）——不要為一致而改語意。
- **⑥a′ 是 v5 的關鍵新增**：它讓「假成功」到不了 cmd 層——若實作時發現 cmd 層還需要收窄歸零邏輯，代表 ⑥a′ 沒放對位置，回查。
- **白名單是回滾槓桿**：正常日出現 exit 3 且 log 顯示「疑似垃圾頁」→ 先確認是不是真無選項券，是就加白名單，不是就查官網改版。
- **煙霧零污染＋計時**：備份還原制；本輪煙霧要量每碼間隔（驗證 ⑦a 生效）。
- **main 前進就先 rebase**；反向測試「該擋的時候真的擋」才算證明。
- 任一層漏改都會被對應案例抓出（3.5 五案例／4.5 四案例／1.4 pacing 單元）。

## 失敗／回滾判準

- 任一落點驗證失敗 → 只回滾該落點；①/②③/④⑤⑧/⑥/⑦ 六組互不依賴，可各自單獨回滾。
- 修改① 誤傷 500/超時重配 → 立即回滾重檢判斷條件。
- ③a 誤傷非關鍵字重試 → 守門員與案例三抓出 → 回滾收緊。
- ⑦ 若煙霧/CI 顯示間隔異常或官網反應變化 → 常數調回 2.0（一行）——⑦ 的回滾成本最低。
- ⑥a 門檻誤傷正常頁（全碼解析失敗＋exit 3）→ 單獨 revert ⑥a。
- ⑥a′/⑥b 誤熔斷（無選項券相鄰）→ 白名單加入該碼；持續誤熔斷 → revert ⑥b 或放寬 N。
- ⑤ gh 服務端故障誤擋一日 → 可接受，次日自動重試，不回滾。
- 上線後正常日 exit 3 → 立即 revert＋重查關鍵字與門檻。
