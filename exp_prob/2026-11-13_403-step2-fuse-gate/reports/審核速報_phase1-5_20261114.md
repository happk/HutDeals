## 唯一實質缺陷：gate 的 case 拼接漏掉單邊空字串

### 位置
[`.github/workflows/scan.yml:40`](../../../.github/workflows/scan.yml#L40)：

```sh
case "$OPEN$OPEN2" in ""|*[!0-9]*) echo "gh 回應非整數（OPEN=$OPEN, OPEN2=$OPEN2）→ gate 失敗"; exit 1;; esac
```

[同檔 L50](../../../.github/workflows/scan.yml#L50) 的 `RUNNING` 用同一個寫法。

### 實測八種輸入

| `OPEN` | `OPEN2` | 實際結果 | 應為 |
|---|---|---|---|
| `0` | `0` | 放行 ✅ | 放行 |
| `1` | `0` | 擋下 ✅ | 擋下 |
| `0` | `1` | 擋下 ✅ | 擋下 |
| **`""`** | **`0`** | **放行 ❌** | **fail-closed 擋下** |
| **`0`** | **`""`** | **放行 ❌** | **fail-closed 擋下** |
| `""` | `""` | 擋下 ✅ | 擋下 |
| `abc` | `0` | 擋下 ✅ | 擋下 |
| `null` | `0` | 擋下 ✅ | 擋下 |

### 機制

拼接 `"" + "0"` 得 `"0"`，匹配 `[0-9]` 因此通過 case 檢查。接著
[`L41`](../../../.github/workflows/scan.yml#L41) 的 `[ "$OPEN" -gt 0 ]` 在 `if` 條件內報
`integer expression expected`，但 `set -e` 對 `if` 條件不生效，判定為假 → 落到 else →
`should_run=true` → **放行**。

實測輸出（Git Bash）：

```
OPEN=''  OPEN2='0'  → exit=0 out=GATE_PASSED | bash: line 8: [: : integer expression expected
```

### 修法

改成兩個獨立判定，各一行：

```sh
case "$OPEN"  in ''|*[!0-9]*) echo "OPEN 非整數（$OPEN）→ gate 失敗"; exit 1;; esac
case "$OPEN2" in ''|*[!0-9]*) echo "OPEN2 非整數（$OPEN2）→ gate 失敗"; exit 1;; esac
```

`RUNNING` 那一處本來就是獨立判定（[L50](../../../.github/workflows/scan.yml#L50)），無此問題。

## 理論邊界，不需修但記錄語意落差

`gh issue list --jq 'length'` 正常必輸出 `0` 或正整數，不會是空字串。
要觸發需「gh 回空字串且 exit 0」，實務罕見。但既然 v6 的立意是「查不到＝擋」，這個縫仍值得補。

另一個觀察：**Phase 6.3 的反向測試不會暴露這個缺陷**——
正常日 `OPEN` 會是 `0` 而非空字串，所以反向測試會通過。缺陷要等真的 gh 異常才出險，
這正是它難被發現的原因。

## 做對的關鍵部分

### ⑦ 節流的位置精確

[`daily.py:213-237`](../../../script/scan/daily.py#L213) 的順序完全正確：

```
L214: d = step2_of(r, fetcher)
L215-221: except（HTTPError 403/429 或 RuntimeError 關鍵字）→ blown=True; break
L222: sleep_scan(i, alive)             ← 每碼節流
L223-236: d is None → bump_parse_streak → 達 N 熔斷
L237: fail_streak = 0                  ← 真成功歸零
```

熔斷 `break` 發生在 `sleep_scan` **之前**——熔斷時不多等 45 秒；
解析失敗的 `continue` 在 `sleep_scan` **之後**——失敗碼仍受節流。

[pacing.py:17-19](../../../script/lib/pacing.py#L17) 的參數：`DEFAULT_SLEEP = 1.0`、
`DEFAULT_SEG_GAP = 0.0`（停用但常數與參數保留），中場休息 `30s / 每 50 發` 不動。
兩支手動工具（`scan_probe.py`、`scan_run.py`）的 argparse 建構實測正常。
