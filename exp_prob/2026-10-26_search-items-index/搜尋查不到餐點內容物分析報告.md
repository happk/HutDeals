## 結論

**問題屬實，且根因不是某處寫錯，而是兩個各自合理的設計互相疊加、沒有接起來**：搜尋索引的欄位清單，與「結構化優先」的資料產出規則，在不同時期各自上線，後者把餐點內容搬進了前者看不到的欄位。全站 723 券中 682 筆（94%）的外部碼受影響——它們的餐點內容只存在 `items[].text`，對搜尋完全隱形。實測搜「黃金雞軟骨」只中 2 筆、實際應中 363 筆。

## 機制鏈

缺口需要兩段代碼共同作用，任一段接起來都不會漏：

1. **直接原因——搜尋索引欄位寫死三個**：[`src/lib/filter.ts:64`](../../src/lib/filter.ts#L64) 的 haystack 只組 `name`＋`description`＋`code`：

   ```ts
   const haystack = `${c.name} ${c.description ?? ""} ${c.code ?? ""}`.toLowerCase();
   ```

   卡片實際渲染給使用者看的餐點候選（[`src/types.ts:MealItem.text`](../../src/types.ts#L8-L10) 的 `items[].text`，如「黃金雞軟骨(小份)」）從頭到尾不在索引裡。這行寫於資料還以 description 為主的年代，當時它涵蓋幾乎全部可見內容，本身合理。

2. **放大器——結構化優先把 description 拿掉**（2026-09-07 P2 決策）：[`script/site/ingest_external.py:72-76`](../../script/site/ingest_external.py#L72-L76) 在拆得出結構化 items 時：

   ```python
   if items:
       description = None
   ```

   理由在顯示層：卡片改用結構化清單呈現，`description` 原文視為冗餘，避免同一份內容顯示兩次。這對顯示是對的；副作用是這些券的餐點內容從此**只存在 items**——一個搜尋看不到的欄位。

**疊加後的結果**：對 682 筆外部碼，搜尋看得到的只剩 `name`（標題，通常只有促銷語如「外帶買大送小」）和 `code`（五位數字）。使用者在卡片上看到「黃金雞軟骨」，搜尋框輸入同樣的字卻命中不了。少數能被搜到的筆，是 `description`（拆不出結構化的 fallback 案例）或標題裡剛好含詞——運氣，不是設計。

## 效能量測

以 [bench_search.mjs](bench_search.mjs) 對真實 coupons.js（723 券）實測（Node 24 桌機；低階行動裝置依慣例 ×5–10 估算）：

| 項目 | 實測 | 低階手機估算 |
|---|---|---|
| 快取建立（一次性，首鍵懶建 723 券） | 7.1 ms | ≤ 70 ms，僅首次 |
| 每鍵·現行（每鍵重建字串，1 詞） | 0.198 ms | ~1–2 ms |
| 每鍵·方案 B（快取，1 詞） | **0.067 ms** | ~0.3–0.7 ms |
| 每鍵·方案 B（快取，2 詞 AND） | 0.050 ms | ~0.3–0.5 ms |
| 記憶體（快取字串 128,082 字元） | ≈250 KB（UTF-16） | 同左，一次性 |

三個結論：

1. **方案 B 每鍵比現行快約 3 倍**：現行每鍵為 723 券重建字串（配置＋GC 壓力）；快取後每鍵只剩 `includes`，零配置。行動端的每鍵成本不到一幀（16 ms）的 5%。
2. **記憶體增量 ≈250 KB**：coupons.js 解析後的物件圖本身已達數 MB，快取僅增加個位數百分比；且懶建——不搜尋的使用者完全不付這個成本。
3. **對照方案 A 反而行動端更吃虧**：A 每次載入多傳 9 KB gzip＋多解析 291 KB JSON（載入關鍵路徑上的 CPU），B 載入零增量、成本只在使用者實際搜尋時發生一次。

量測另驗證正確性：同詞「雞軟骨」現行命中 2 筆、方案 B 命中 363 筆，與缺口規模一致。

## 建議

**方案 B＋WeakMap 懶快取**：[`filter.ts`](../../src/lib/filter.ts) 加模組級 `WeakMap<Coupon, string>`，每券物件首次被搜時組一次 haystack（現行三欄＋該券 `items[].text` 去重 join），之後每鍵零重建。todo.md 記錄的「每次輸入要掃 13 萬字元」疑慮由懶快取消除；方案 A 多付的 291 KB 反常規化欄位，換不到方案 B 沒有的好處。
